# DataGrid Release 2 (Finding rows) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let people find rows in `DataGrid`: a filter strip with text, select and multi-select
filters, all/any match mode, wildcard search, the filter badge, the filtered-empty state,
`initialQuery`, and the query's debounce, in both data modes.

**Architecture:** The query (sorting, filters, match mode, search) moves out of `DataGrid.tsx` into a
`useGridQuery` hook that is the single place a query changes, and runs one change routine (clear the
selection, scroll to the top, restart server paging, tell the app). Matching is a pure module,
`query.ts`, that the grid uses in client mode and the stories' mock server uses in server mode, so both
agree. The filter strip is a second row of the sticky `<thead>`, so it scrolls sideways with the
columns and is part of the grid's keyboard model; every row below it shifts down one keyboard row while
it shows. `IconButton` gains an optional pressed state and count badge.

**Tech Stack:** React 19, TypeScript, `@tanstack/react-table` ^9 (no new feature modules), Base UI
`Combobox` (`@base-ui/react/combobox`, already installed at 1.8.0), CSS Modules on tokens, Vitest +
Testing Library + vitest-axe, Storybook 10.

**Spec:** `docs/superpowers/specs/2026-11-04-data-grid-design.md`. Read "Data and query", "Filtering
and search", "States" and "Keyboard and screen readers" first. This plan covers its release 2 only.

## Review Focus

1. **A pending debounce racing a reset.** The user types in a text filter or the search field, and
   before the delay ends presses "Clear filters" (or the query resets another way): the stale text
   must not come back when the timer fires, and the field shows the cleared value. Test in Task 4
   (search) and Task 5 (text filter).
2. **Server rows for an old query.** After a filter or search change in server mode, the old rows stay
   visible, `onLoadMore` does not fire for them, and the grid waits for a new `rows` array, exactly as
   a sort change does in release 1. Test in Task 7.
3. **Search terms full of regex characters.** `a.b`, `(x`, `[1]`, `c:\temp`, `50%+` match literally;
   only `*` and `?` are wildcards; an unclosed bracket never throws. Test in Task 2.
4. **Toggling the strip with the tab stop in the body.** The grid's tab stop stays on the same body
   cell when the strip opens or closes, even though every body row moves down or up one keyboard row.
   Test in Task 5.
5. **Rows the user can no longer see.** In client mode, a filter that hides the highlighted row clears
   the highlight, the selection is cleared by the query change, and select-all afterwards selects only
   the matching rows. Test in Task 3.

```ts
/** The id TanStack gives a column definition. */
export function columnIdOf(column: DataGridColumnDef<RowData, unknown>): string | undefined;
/** The column's header when it is a string, else its id: the name in "Filter by <name>". */
export function columnNameOf(column: DataGridColumnDef<RowData, unknown>): string;
/**
 * A search term as a case-insensitive, unanchored RegExp: `*` is any run of characters, `?` is one
 * character, everything else is literal. The term is trimmed; an empty term gives null.
 */
export function dataGridSearchPattern(term: string): RegExp | null;
export const emptyDataGridQuery: DataGridQuery; // { sorting: [], filters: {}, matchMode: 'all', search: '' }
/**
 * A full query from a partial one, keeping only what can apply: text values and the search
 * trimmed, empty values dropped, and filters dropped whose column is unknown, has no filter, or
 * whose value has the wrong shape (a string for `text` and `select`, a non-empty string array for
 * `multiSelect`).
 */
export function normaliseQuery<Row extends RowData>(
  query: Partial<DataGridQuery> | undefined,
  columns: readonly DataGridColumnDef<Row, unknown>[],
): DataGridQuery;
/** Active column filters plus one for a search: the filter button's badge. */
export function countActiveCriteria(query: DataGridQuery): number;
/** Whether two queries are the same, value for value. */
export function isSameQuery(first: DataGridQuery, second: DataGridQuery): boolean;
/**
 * A predicate for rows that match a normalised query, or null when the query has no filters and
 * no search. Search and the filters combine with AND; the filters with each other by `matchMode`.
 */
export function createQueryMatcher<Row extends RowData>(
  columns: readonly DataGridColumnDef<Row, unknown>[],
  query: DataGridQuery,
): ((row: Row) => boolean) | null;
```

Matching rules (all read the column's text through `textValueOf`; a row whose column has no text
never matches that column's filter):

- `text`: the text, lower-cased, contains the filter value, lower-cased. No wildcards.
- `select`: the text equals the value exactly.
- `multiSelect`: the text equals one of the values.
- search: some column with `searchable !== false` has text the pattern matches.

`columnIdOf` follows TanStack v9's rule: `id`, else `accessorKey` with every `.` replaced by `_`,
else `header` when it is a string. The test in step 1 that compares it with a real table is the
authority; if TanStack's rule differs, follow TanStack.

```ts
export interface DebouncedDraft {
  draft: string;
  /** Sets the draft and commits it after the delay. */
  change: (value: string) => void;

/**
```
