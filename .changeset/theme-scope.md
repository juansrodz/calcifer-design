---
'@calcifer-design/ui': minor
---

Add `ThemeScope` and `usePortalContainer`, so an app can restyle the library inside one part of a page. `ThemeScope` takes a theme from `defineTheme` in `@calcifer-design/tokens` and applies it to everything inside it. Every dialog, menu, select, tooltip, toast, date picker, tree select and nav menu opened from within a scope renders inside that scope, so it wears the scope's theme and stays within its box, and `usePortalContainer` gives your own overlays the same place to render. Scopes nest and can be pinned to light or dark; an unpinned scope follows `<html>`'s `data-theme` and then the operating system, never an outer scope's pin. With no scope mounted nothing changes. Components now read the theme's tokens for headings (the display font), body text (the body font), font weights, six purpose radii, shadows by surface, the selected and nav colours, the control floors and the drawer width, and every default equals the value 0.6.0 used. Two things look different under the house theme: the end drawer's leading corners now round at `--radius-dialog`, 16 px (R4), and `Card` and `Descriptions` headings go from weight 700 to 600 (R22). A third, smaller change comes with R5, which sizes overlays from their fixed viewport in percentages, as it does `ToastRegion`'s width: the centred dialog's height cap is 85% of its padded viewport rather than `85dvh`, up to about 27 px shorter when standalone. Class names now carry the package version (R7), so two versions of ui on one page never share a class.

To upgrade, move `@calcifer-design/tokens` to `^0.3.0` together with ui and import `tokens.css` from it. ui's own dependency on tokens now requires `^0.3.0`, and ui reads names that only that file declares, so with an older `tokens.css` the control size, radii, shadows, selected colour and heading weight are missing. Components read role tokens, not the variables an app may override by hand. Segmented's pressed option, the Tabs indicator and `DatePicker`'s selected day read `--color-selected` and `--color-selected-text`, not `--color-accent`; `NavMenu` reads `--color-nav-*`; Segmented's track and border read `--color-segmented-*`; radii, sizes and shadows follow the same rule. An app that restyles by overriding `--color-accent` or another house variable directly should move to `defineTheme` and `themeToCss`, or also override the role tokens. One known limit: the end drawer's rounded corners and its slide are physical, so right-to-left layouts are not supported yet.
