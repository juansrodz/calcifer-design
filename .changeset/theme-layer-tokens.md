'@calcifer-design/tokens': minor
---

Add a theme API, so an app can restyle the whole library from one definition. `defineTheme` builds a theme from overrides of the library's tokens, with room for the app's own tokens under a prefix of its choosing. `themeToCss` turns that theme into a complete stylesheet scoped to a class, which follows the `data-theme` attribute on `<html>` and then the operating system's colour preference, and has blocks that pin one scope to light or dark. `checkThemeContrast` holds a theme to the library's text and component colour pairs, with named exemptions for brand colours that cannot pass and room for extra pairs of the app's own. `findUnknownCustomProperties` and `customPropertyNamesOf` find every `var(--name)` that a stylesheet reads but nothing declares, so a misspelled token fails a check instead of rendering as nothing. The token set grows to give a theme more to change: `font.display` and `font.body`; the `fontWeight`, `fontStretch` and `textTransform` families; six purpose radii (`control`, `option`, `panel`, `popup`, `card` and `dialog`); `size.drawer`, `size.control` and `size.controlSm`; the `selected`, `inverse`, `nav`, `tabBar`, `segmented`, `sheetHandle`, `scrimSheet` and `avatar` colours; and ten `shadow` keys. Every new token's default equals the value the library already used for that role, so `tokens.css` changes no consumer's look. The two intended look changes in this release land with the ui package's own changeset.
